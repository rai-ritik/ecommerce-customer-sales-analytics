# Excel Analysis Guide

## Overview

This document describes how to use Microsoft Excel for exploratory analysis and pivot-based reporting on the E-Commerce Customer & Sales Analytics project. Excel is used for:

- Interactive data exploration.
- Pivot table summaries.
- Quick charts and visualizations.
- Ad-hoc analysis and what-if scenarios.

All analysis starts from the cleaned Parquet file or the exported CSV files in `docs/`.

---

## Prerequisites

### Required files

Ensure the following files exist locally (generated by Python pipelines):

- `data/processed/clean_sales.parquet` — Cleaned sales transactions (524,878 rows).
- `docs/sales_profile.csv` — Overall KPI summary.
- `docs/monthly_sales.csv` — Monthly revenue, orders, units, customers.
- `docs/country_sales.csv` — Revenue by country (38 countries).
- `docs/product_sales.csv` — Revenue by product (3,922 products).
- `docs/customer_sales.csv` — Revenue by customer (4,338 customers).
- `docs/rfm_customers.csv` — RFM scores and segment labels.
- `docs/rfm_segments.csv` — RFM segment summary.

### Convert Parquet to CSV (if needed)

Excel cannot read Parquet directly. If you need the full cleaned dataset in Excel:

```python
# In python/ directory, run:
import pandas as pd

df = pd.read_parquet("data/processed/clean_sales.parquet")
df.to_csv("data/processed/clean_sales.csv", index=False)
```

⚠️ **Warning:** The full cleaned dataset has 524,878 rows. Excel handles this, but large files may be slow. For most analysis, use the aggregated CSV files in `docs/`.

## Sheet-by-sheet setup

### 1. Cleaned Data (optional)

**Source:** `data/processed/clean_sales.csv`

**Purpose:** Full transaction-level data for detailed exploration.

**Setup:**
1. Open Excel → Data → Get Data → From File → From Text/CSV.
2. Select `data/processed/clean_sales.csv`.
3. Click "Load" (or "Transform Data" if you need to adjust types).

**Key columns:**
- `invoice_no` — Invoice identifier.
- `stock_code` — Product code.
- `description` — Product description.
- `quantity` — Units sold (positive for sales, negative for returns).
- `unit_price` — Price per unit.
- `revenue` — Calculated as `quantity * unit_price`.
- `invoice_date` — Transaction date and time.
- `customer_id` — Customer identifier (may be blank).
- `country` — Customer country.
- `year`, `month`, `day`, `hour` — Calendar fields.
- `is_cancellation` — Flag for invoice numbers starting with "C".
- `is_return` — Flag for negative quantities or cancellations.

**Use cases:**
- Filter by date range, country, or product.
- Create ad-hoc pivot tables.
- Export subsets for further analysis.

### 3. Monthly Revenue

**Source:** `docs/monthly_sales.csv`

**Purpose:** Analyze revenue trends over time.

**Setup:**
1. Data → Get Data → From File → From Text/CSV.
2. Select `docs/monthly_sales.csv`.
3. Load to a new sheet named `Monthly Revenue`.

**Create a pivot table:**
1. Insert → PivotTable → Select the `Monthly Revenue` data.
2. Place pivot table in a new sheet or next to the data.
3. Fields:
   - Rows: `year_month` (or `year` and `month` separately).
   - Values: `revenue`, `orders`, `units_sold`, `customers`.
4. Format revenue as currency (£).

**Create a line chart:**
1. Select the pivot table's revenue column.
2. Insert → Line Chart → 2-D Line.
3. Add chart title: "Monthly Revenue Trend".
4. Add data labels if needed.

**Key findings:**
- November 2011: £1,503,866.78 (strongest month).
- September 2011: 39.40% month-over-month growth (largest increase).
- December 2011: Incomplete data (only through December 9).

**Use cases:**
- Identify seasonal patterns.
- Plan inventory and marketing for peak months.
- Track growth trajectory.

### 4. Country Analysis

**Source:** `docs/country_sales.csv`

2. Select `docs/country_sales.csv`.

### 7. RFM Segments

**Source:** `docs/rfm_customers.csv`

**Purpose:** Analyze individual customer RFM scores and segments.

**Setup:**
1. Data → Get Data → From File → From Text/CSV.
2. Select `docs/rfm_customers.csv`.
3. Load to a new sheet named `RFM Segments`.

**Key columns:**
- `customer_id` — Customer identifier.
- `recency` — Days since last purchase (as of 2011-12-10).
- `frequency` — Number of distinct invoices.
- `monetary` — Total revenue.
- `r_score`, `f_score`, `m_score` — Quintile scores (1–5).
- `rfm_score` — Sum of r_score + f_score + m_score.
- `rfm_code` — Three-character code (e.g., "555").
- `segment` — Segment label (e.g., "Champions").

**Create a pivot table:**
1. Insert → PivotTable → Select the `RFM Segments` data.
2. Fields:
   - Rows: `segment`.
   - Values: `customer_id` (count), `monetary` (sum).
3. Sort by monetary descending.

**Use cases:**
- Look up individual customer segments.
- Create targeted marketing lists.
- Validate RFM assignments.

## Tips and best practices

### Data refresh

If underlying CSV files change:

1. Data → Refresh All.
2. Excel will update pivot tables and queries.

### Performance

- Use aggregated CSV files (`docs/*.csv`) instead of the full cleaned dataset for faster analysis.
- Limit pivot tables to top N items (e.g., top 20 products).
- Avoid volatile functions (e.g., `NOW()`, `RAND()`) in large sheets.

### Formatting

- Format revenue as currency (£).
- Format percentages with 1–2 decimal places.
- Use consistent date formats (YYYY-MM-DD or MMM YYYY).

### Validation

- Cross-check pivot table totals against `docs/sales_profile.csv`.
- Verify revenue sums match expected values.
- Ensure customer counts reconcile with RFM segment totals.

## Limitations

- Excel cannot directly read Parquet files; convert to CSV first.
- Large datasets (500k+ rows) may be slow in Excel.
- Complex calculations (e.g., RFM scoring) are better done in Python.
- Excel analysis is not automatically reproducible; document steps carefully.
